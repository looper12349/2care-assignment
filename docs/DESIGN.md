# CarePath — design note

**Scope.** A synthetic adult patient books a new routine primary-care appointment. The Next.js/TypeScript interface supports patient chat, staff handoffs, feedback, and evaluation. Cancellation, rescheduling, proxy booking, and medical decisions route to staff. Mock sessions demonstrate access checks; they are not real identity verification.

**Architecture.** Four application services: Next.js Web; Conversation API with LangGraph; Scheduling API; Evaluation API/worker. Docker adds one PostgreSQL infrastructure container with three separately owned databases and restricted roles. Conversation has a PostgreSQL checkpointer, cross-replica advisory locks, and an audited shared behavior registry. Scheduling owns transactional capacity and operation receipts. Evaluation has durable database-clock leases with stale-owner rejection. HTTP connects services; the shared Python package keeps implementation small. The local launcher retains a single-host SQLite fallback. LangChain can supply checked interpretation; domain code controls actions.

**Safe booking.** Each conversation belongs to a trusted clinic/patient identity. A proposal captures the exact offered appointment and request version. A correction clears earlier confirmation. Booking requires current consent and a stable operation reference. Scheduling independently checks scope, capacity, and operation identity. Lost replies trigger lookup of the original operation; uncertain outcomes cannot authorize a second booking. Handoffs have persisted tickets and honest status. Emergency wording interrupts routine scheduling; synthetic phrase checks are not clinical triage.

**Memory and feedback.** LangGraph checkpoints retain current requirements, options, proposal, and progress. Appointment receipts remain authoritative in Scheduling. Patient ratings/comments are separate feedback records, not instructions or automatic policy changes. Cross-session preference memory is outside this implementation.

**Evaluation and improvement.** LangSmith is the only scenario evaluation framework. Twenty-two complete scripted conversations run in fresh synthetic worlds with a fixed clock; two variations are held out from candidate generation. Scoring inspects persisted appointments, operations, handoffs, and event order, because a transcript cannot prove those effects. Baseline failures produce structured evidence. A typed artifact can only enable one availability refresh after a definite slot conflict, preserve requirements, and demand fresh consent. It activates a reviewed branch; it does not rewrite code or train model weights. The entire suite is rerun. Missing evidence, critical violations, or case-level regressions reject the candidate. Staff activation recomputes gates and affects new conversations only.

**Measured result and limits.** Three repetitions yielded v1 **60/66**, v2 **66/66**, zero critical violations, and no regressions. These are actual local LangSmith SDK runs with a deterministic interpreter, disposable SQLite fixtures, and uploads disabled. Separate integration tests exercise PostgreSQL coordination. The result proves this bounded loop, not model reliability. Live interpretation/cloud experiments require credentials and remain unverified. Real deployment still needs verified identity, clinic-approved policy, a real scheduling adapter, retention rules, and operating budgets; PostgreSQL alone does not provide those.

**AI and judgment.** AI helped research, code, document, and generate cases. The user's decisions set separate services, Next.js, and LangSmith-only evaluation. Engineering judgment kept authorization and booking integrity outside the model, bounded the improvement, and required independent side-effect evidence. Synthetic passing scores were explicitly not treated as approval for a real clinic.
